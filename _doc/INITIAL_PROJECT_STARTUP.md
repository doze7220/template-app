# AI駆動開発（AIdd）新規プロジェクト立ち上げガイド（Claude Code 版）
本ドキュメントは、このスターターキット（GitHub のテンプレートリポジトリ `template-app`）から新しいプロジェクトを立ち上げ、最初の Phase に入るまでの手順である。Claude Code のセッションで本書を読ませ、「新プロジェクト立ち上げの対話を開始して」と伝えれば、Claude が以下の手順を先導する。

---

## 0. 準備（人間）
1. GitHub の `template-app` で「Use this template」から新しいリポジトリを作り、ローカルにクローンする（GitHub を使わない場合は、本フォルダを `.git` を除いてコピーし、`git init` する）。
2. Claude Code（デスクトップアプリの Code タブ等）でそのフォルダを開き、新しいセッションを始める。

---

## 1. 全体像

```
[Step 1: 企画アイデアの提示 (人間 -> Claude)]
      │
      ▼
[Step 2: 憲法の最適化（PROJECT_CONSTITUTION.md / CLAUDE.md / README.md）]
      │
      ▼
[Step 3: 全体見取り図の構築（PROJECT_ARCHITECTURE.md）]
      │
      ▼
[Step 4: 運用ファイルの初期化（PROJECT_MILESTONE.md / COWORK_STATUS.md）→ 初回コミット]
      │
      ▼
[Step 5: Phase 1 の親セッション開始（スキル oz-dir-session）]
```

立ち上げセッション自体は Phase に属さない。Step 4 のコミットで終了し、Step 5 は**新しいセッション**で始める（立ち上げ時の会話を Phase に持ち込まないため）。

---

## 2. 各ステップ

### Step 1: 企画アイデアの提示
人間（発注者）は、作りたいアプリのアイデア、技術スタック、将来構想を自由に提示する。

### Step 2: 憲法の最適化
Claude は、提示内容に基づき次を書き換えて提案する。
1. `PROJECT_CONSTITUTION.md` の **1章（プロジェクト基本定義）** と **3章（絶対禁止事項）**。その技術スタックでの暴走防止ルール、責務分離、グローバル汚染禁止、コメント規格（JSDoc / Doxygen 等）、ファイル先頭の責務定義の書き方を定める。
   * 2章・4章（手続き的なルール）は普遍的なため書き換えない。
2. `CLAUDE.md` 冒頭のプロジェクト概要、`README.md` の概要。

### Step 3: 全体見取り図の構築
Claude は、次の要素に絞った初期 `PROJECT_ARCHITECTURE.md` を作成して提案する。
1. 物理フォルダ構造（`_doc/`・`_log/` 等のアンダースコアフォルダと、モジュール配置ルール。`_log/dir/` は記載しない）
2. データ構造（Model）の初期定義
3. 各フォルダ・モジュールの責務マッピング（何を書いてよく、何を書いたら責務違反になるかの境界線）
* 関数の中身やロジックはコード自身（ドキュメントコメント）を SSOT とするため、ここには書かない。
* 雛形冒頭の「立ち上げ前」注記コメントは、完成時に削除する。

### Step 4: 運用ファイルの初期化と初回コミット
1. `_doc/PROJECT_MILESTONE.md` に Phase 大番号の並びと機能バックログの初版を書く。
2. `_doc/COWORK_STATUS.md` のプロジェクト現況を「立ち上げ完了・Phase 1 未着手」に更新する。
3. 発注者の承認を得て、初回コミットを行う。

### Step 5: Phase 1 の開始
新しいセッションで「`oz-dir-session` で Phase 1 を始めて」と伝える。以後の流れは `_doc/PROJECT_README.md` 4章を参照。

---

## 3. 【Claude 向け】立ち上げ時の動作方針
* **実装を急がない**: アイデアを聞いていきなりコードや詳細ロジックを提示しない。まず「憲法」と「アーキテクチャ」という統治の壁を作ることに集中する。
* **三層のガバナンスを意識する**: 「プロジェクト憲法」「アーキテクチャ定義書」「各モジュール先頭の責務定義」の三層が機能するよう、初期案を書く。
* **各 Step で発注者の承認を得てから次へ進む。** コードファイル（実装）は立ち上げセッションでは一切作らない。最初の実装は Phase 1 の REQ セッションで行う。
* 「新プロジェクト立ち上げの対話を開始して」と言われたら、まずどんなアプリを作りたいか、技術スタック、将来構想をヒアリングすることから始める。
