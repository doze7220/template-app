# OZ Vector Editor

HTML5 Canvas と Vanilla JS (ES Modules) で動作する、ゲーム用ベクターグラフィック作成・JSコード書き出しエディタです。
同一頂点数での滑らかなモーフィング（線形補間 - Lerp）に対応したグラフィックデータを視覚的に作成し、そのままゲームに組み込めるクリーンなコードとして書き出すことができます。

---

## 🚀 特徴
- **完全スタンドアロン & ビルド不要**: 外部フレームワークやビルドツール（Webpack, Vite等）を一切使用せず、単一の HTML、CSS、標準の ES Modules のみで構成されています。ローカルの HTML ファイルをブラウザでダブルクリックするだけで即座に起動します。
- **ゲーム特化型ベクタージェネレーター**: 描画したベクターデータを JavaScript コードとしてエディタから直接書き出し可能。ゲームエンジンや自作フレームワーク側で動的にインポートして描画できます。
- **モーフィング（Lerp）完全対応**: 「状態A」から「状態B」への頂点スライド（線形補間）を保証するため、同一頂点数固定のトポロジー同期ロジックを搭載しています。
- **AI駆動開発（AIdd）に完全最適化されたガバナンス環境**: 実装AIの暴走を防ぎ、高い品質と一貫性を保ちながら自律開発を行うための強固な統治システムをリポジトリレベルで内包しています。

## 🛠️ プロジェクト構造 (Directory Layout)
AI-IDEの不要なインデックス汚染や、GitHub Pages等でのビルドエラーを完全に排除するため、論理的かつ厳格に隔離されたディレクトリレイアウトを採用しています。

```text
.
├── index.html                  # エントリポイント（アプリ起動用）
├── css/
│   └── style.css               # スタイリング
├── js/                         # Vanilla JS / ES Modules ソースコード
│   ├── main.js                 # アプリ起動・ブートストラップ
│   ├── core/                   # アプリケーション基盤
│   ├── models/                 # データ管理層（VectorModel等 - 状態のみを保持）
│   ├── views/                  # 描画・UI層（CanvasManager等 - 描画とインタラクション）
│   └── utils/                  # 算術・ヘルパー関数
├── _doc/                       # 発注者用ドキュメント群（AI-IDE参照用テンプレート等）
│   ├── PROJECT_AI_WORKFLOW.md  # 人間と設計AIのための発注ワークフロー
│   └── TEMPLATE_REQ_*.md       # 指示書（REQ）テンプレート
└── _log/                       # AI駆動開発の実行履歴ログ（親のみアンダースコアでJekyllビルド回避）
    ├── req/                    # 実際に出された作業指示書 (YYYYMMDD_HHMM_REQ_*.md)
    ├── res/                    # 実装AIが出力した計画・報告書 (YYYYMMDD_HHMM_RES_*.md)
    └── TEMPLATE_RES_*.md       # 報告書（RES）テンプレート
```

## ⚖️ AI駆動開発 (AIdd) ガバナンスシステム
本プロジェクトは、AIと人間が完璧な主従関係のもと、破綻することなく並行開発を進めるための「AI統治システム」を実装しています。

### 1. 三層の絶対ルール
- **プロジェクト憲法 (`PROJECT_CONSTITUTION.md`)**:
  AIが従うべき普遍的な法秩序・手続（REQ/RESプロセス、指定外ファイル参照の絶対禁止、Vanilla JS原則、JSDoc義務化等）を定義。すべての作業における最上位の法律です。
- **アーキテクチャ定義書 (`PROJECT_ARCHITECTURE.md`)**:
  各フォルダおよび論理クラスの「責務の境界線」を定義した見取り図。AIが「どのファイルを触る際、どの個室に留まるべきか」を厳格に拘束します。
- **ファイル先頭の『責務定義』**:
  すべての `.js` ファイルの先頭に、JSDocでそのモジュールの「単一の責務（Responsibility）」を明記。コードを書き換えるAIがその境界線を踏み越えるのを最前線で防ぎます。

### 2. REQ / RES 駆動プロセス (Request & Response)
開発におけるすべての作業は、非対称・非同期なドキュメントの往復によって統治されます。

1. **REQ（指示書）の発行**: `./_log/req/` に具体的な実装要件を記述した指示書を発行。AIに「計画立案」か「即時実行」かを厳密に命令します。
2. **RES（計画・報告書）の返答**: `./_log/res/` に、AI自身が分析した「アーキテクチャ設計」「ファイル影響範囲」「細分化されたタスクリスト」を自己申告させます。
3. **1タスク・1チャットの実装**: 承認されたRESのタスクリストに基づき、AIに「1回のやり取りで1つのタスクだけ」を確実にコードへ反映させ、RESのチェックボックスを [x] に更新させます。

## ⚡ 起動方法
1. 本リポジトリをローカル環境にクローン、またはダウンロードします。
2. `index.html` を任意のウェブブラウザ（Chrome, Firefox, Safari, Edge等）でダブルクリックして開きます。
3. ビルドプロセスやローカルサーバー（Live Server等も推奨されますが必須ではありません）を必要とせず、そのまま開発・実行が可能です。
